# RustClipSync Desktop 0.5.0

Upgrade together with RustClipSync Server **3.0.0**. This release requires wire
protocol **3**, with rustclipsync-core **0.4.0**. Older clients need server 2.0.0.
Mobile applications and Fcitx input methods are released separately.

- Report send-only, receive-only or bidirectional policy before receiving, and
  report pause separately. Direction changes, reconnects and manual actions keep
  local filters and wait for server confirmation. WSS has authenticated HTTP fallback.
- Use fenced device sessions and server-filtered per-device delivery. Reconnect
  replay is at most the latest eligible message inside the server-configured window;
  the desktop client does not hardcode that window.
- Preserve device identity, encrypted local state/history and sensitive inbox.
  Marked sensitive synchronization and automatic sensitive clipboard writes remain
  off by default. Disabling sensitive synchronization does not block ordinary receives.
- Update the exported shared-core snapshot to the released 0.4.0 source. The core's
  opt-in conflict-recovery API does not silently override desktop conflict policy.
- Fix Windows acceptance around disabled controls, asynchronous settings/history,
  direction confirmation and the sensitive-settings scroll target.
- Publish native Windows x64 plus Debian 12, Ubuntu 24.04, Fedora 43 and Arch x86_64
  installers with combined SHA-256 checksums after platform checks pass.

Windows installers remain **unsigned**. Linux requires the documented Qt runtime
and desktop clipboard/Secret Service support; GNOME Wayland without data-control
is unsupported. Server plaintext visibility and end-to-end encryption limitations
remain unchanged.
