# RustClipSync Desktop 0.5.1

Fix desktop synchronization becoming stuck at "Direction not confirmed by the
server" after a temporary clipboard error, even with bidirectional mode selected.

- Keep the configured session when a clipboard read or write fails. Retry with
  the existing exponential backoff, capped at 30 seconds, preserving direction,
  pairing, pending work and the core's protection against uncertain writes.
- Restore the selected direction, pause and sensitive-content settings whenever
  constructing a live session. An unavailable server leaves the local selection
  intact; the shared core confirms the direction before accessing data.
- Apply the recovery fix to both Windows and Linux. Add native regression checks
  covering all three directions, paused/unpaused states, offline reporting and
  repeated session construction with encrypted state preserved.
- Keep the application display name as RustClipSync, with the version shown
  separately in About.

This is a desktop-only patch. Server 3.0.0, protocol 3, rustclipsync-core 0.4.0 and
the persisted data formats remain compatible. Existing paired devices can upgrade
without re-pairing. Omaclipsync and the Android input method need no update for
this fix.

Includes Windows x64, Debian 12, Ubuntu 24.04, Fedora 43 and Arch x86_64 installers
with combined SHA-256 checksums. Windows installers remain **unsigned**.
