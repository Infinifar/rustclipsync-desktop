Runtime resource improvements, released together for Windows and Linux.

- Windows starts with only the Home page. Appearance, Shortcuts, Settings and embedded history are created on first use, then reused to preserve page state.
- Main-window status polling pauses when the window is minimized or hidden and refreshes immediately on restore. The Rust agent keeps syncing, and the sensitive inbox window refreshes independently.
- History pages are cached by storage instance, revision and query. Unchanged pages are neither fetched nor rebuilt. Pagination generates only the current page previews, copying reads only the selected item, and no-op cleanup avoids cloning the entire history.
- Linux detects history storage instance changes, preventing stale cached pages after an agent restart with the same revision. Packages are available for Ubuntu 24.04, Debian 12, Fedora 43 and Arch x86_64.
- Native UI regression checks cover deferred creation, minimized polling, restore refresh, pagination, search and favorites.

With 16 MiB of synthetic history, a page read allocates about 36 KB, and 100 consecutive no-op cleanups allocate zero bytes. These figures measure allocation traffic, not a reduction in resident memory. See the [validation records (Chinese)](https://github.com/Infinifar/rustclipsync-desktop/blob/main/VALIDATION.md).

Windows continues to use shared .NET 10 Runtime and Windows App Runtime 2.6.4 x64, with official download links for missing dependencies. The Windows installer is still unsigned. See the [installation guide (Chinese)](https://github.com/Infinifar/rustclipsync-desktop/blob/main/WINDOWS.md).
